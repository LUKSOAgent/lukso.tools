# How to decrypt .credentials (for AI Agent)

When you need access to credentials in this workspace, decrypt the file as follows.

## Prerequisites

- **SOPS** must be installed (`sops --version`).
- The age **private key** must be available. SOPS looks for it at:
  - `$SOPS_AGE_KEY_FILE` if set, otherwise
  - `~/.config/sops/age/keys.txt`
- Run commands from the **workspace root**: `/root/.openclaw/workspace` (or `~/.openclaw/workspace`).

## Decrypt and use

1. **Decrypt to stdout** (safe: nothing written to disk):
   ```bash
   cd /root/.openclaw/workspace && sops --decrypt .credentials
   ```
   Use this when you only need to read values (e.g. into context). Pipe to `head -n N` if you only need the first N lines.

2. **Decrypt a specific section or line** (example):
   ```bash
   cd /root/.openclaw/workspace && sops --decrypt .credentials | grep -A 2 "Twitter API"
   ```

3. **Edit in place** (decrypt → edit → re-encrypt automatically):
   ```bash
   cd /root/.openclaw/workspace && sops .credentials
   ```
   Only use when the user asks you to **change** credentials. This opens `$EDITOR`; on save and exit, SOPS re-encrypts the file.

## Rules

- **Do not** write decrypted content to a file unless the user explicitly asks (e.g. to restore a backup). Prefer piping or reading into context.
- **Do not** echo or log decrypted secrets. Use them only for the intended task (API calls, config, etc.).
- The file `.credentials` in the workspace is **encrypted**. Never assume its on-disk content is readable; always use `sops --decrypt .credentials` to read it.

## Quick reference

| Need to…              | Command |
|-----------------------|--------|
| Read credentials      | `sops --decrypt .credentials` (from workspace root) |
| Read first 5 lines    | `sops --decrypt .credentials \| head -5` |
| Edit credentials      | `sops .credentials` (opens editor, re-encrypts on exit) |
