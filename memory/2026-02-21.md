### Technical Discussion: Locked LP + Fee Retention Pattern (Kaliyuga / @KaliYuga_e119)

**Contact:** Kaliyuga (Telegram: @KaliYuga_e119, id:1442959428) — LUKSO community member, technical

**Pattern discovered/designed:**
"Burned LP with fee retention" — lock a Uniswap V3 / Universal Swaps LP position permanently while retaining the right to claim fees. LSP-native, no custom smart contract.

**Setup:**
1. Create a normal UP ("Lock Liquidity" UP)
2. Add main UP as controller: CALL permission + AllowedCalls restricted to `collect()` selector `0xfc6f7865` on UNIV-V1-POS `0x855BB3e40261A73Dd4fc691fc024cc7d60794D00`
3. Transfer LP NFT to vault UP
4. Remove initial controller permissions

**Key technical points:**
- AllowedCalls key: `0x4b80742de2bfc6dd6b3f0000<address>`
- Permissions key: `0x4b80742de2bf82acb3630000<address>`
- CALL permission bit: `0x800`
- collect() selector verified: `0xfc6f7865` = keccak256("collect((uint256,address,uint128,uint128))")
- LSP6 AllowedCalls = contract-level + selector-level, NOT parameter-level (no per-tokenId restriction)
- Per-tokenId restriction → requires one vault UP per LP position
- `setDataForTokenId` on Universal Swaps is irrelevant — fee auth is based on LSP8 ownership/operator
- Token `0x...0821` owner confirmed: `0xe11999eCae4C2Cd5E719577f71fAE32D5f6BC4d0`
- Universal Swaps contracts: UNIV-V1-POS `0x855BB3e40261A73Dd4fc691fc024cc7d60794D00`, UniversalRouter `0x6EDaC58326277F1Baf277C41740Db1ff8d7ab13c`

**Security gap identified:**
- Hidden controllers (set without updating AddressPermissions[] array) are undetectable
- Mitigation: verify no listed controller has CHANGEOWNER|ADDCONTROLLER|EDITPERMISSIONS (bits 0x7)
- Full solution: **Vault Factory** — deploy + configure + remove initial controller atomically
- LSP23 LinkedContractsFactory (already on LUKSO mainnet) can achieve atomic setup via postDeploymentModule
- This tooling doesn't exist as a UI yet — gap in the ecosystem

**LUKSO uniqueness:**
- ETH/Base requires custom Solidity BurnLock contract for equivalent pattern
- LUKSO: standard UP + LSP6 = no custom contract needed
- "Vault UP" = just a normal UP used as a locked container (not a special contract type)
- LSP9 Vault: adds indirection without benefit for this use case; no own KeyManager
