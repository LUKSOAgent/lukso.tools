### Standards Learned

**Core LSP Standards:**
- **LSP0 (ERC725Account):** Foundation for Universal Profiles, combines ERC165, ERC725X, ERC725Y, ERC1271, LSP1, LSP14, LSP17, LSP20
- **LSP6 (Key Manager):** Permission system with granular access control, multiple controllers, SUPER permissions
- **LSP7 (Digital Asset):** Fungible tokens (improved ERC20), force parameter, token hooks, divisible/non-divisible
- **LSP8 (Identifiable Digital Asset):** NFT 2.0 with bytes32 tokenIds, flexible formats, per-token metadata
- **LSP1 (UniversalReceiver):** Notification system for incoming transactions, delegates for custom logic
- **LSP2 (ERC725YJSONSchema):** Metadata encoding format, Singleton/Array/Mapping/MappingWithGrouping
- **LSP3 (Profile Metadata):** Universal Profile metadata structure
- **LSP4 (Digital Asset Metadata):** Token/NFT metadata standard
- **LSP5 (ReceivedAssets):** Track received tokens automatically
- **LSP9 (Vault):** Secure asset container with ERC725X/Y capabilities
- **LSP10 (ReceivedVaults):** Track owned vaults
- **LSP12 (IssuedAssets):** Track created/issued tokens

## Key Concepts Mastered

### Universal Profiles (UP)
- Smart contract-based accounts (not just wallets)
- LSP0 + LSP3 metadata + LSP6 Key Manager
- Extensible, upgradable, notification-capable
- Can be owned by EOAs, multisigs, or other smart contracts

### Permission System (LSP6)
- Controllers = permissioned addresses (EOAs or contracts)
- Permissions stored in UP's ERC725Y storage (not in Key Manager)
- Basic permissions: CHANGEOWNER, ADDCONTROLLER, EDITPERMISSIONS, CALL, TRANSFERVALUE, SETDATA, etc.
- SUPER permissions skip restriction checks (cheaper gas)
- AllowedCalls: restrict interactions to specific contracts/functions/standards
- AllowedERC725YDataKeys: restrict which data keys can be set

### Token Hooks (LSP1)
- LSP7/LSP8 notify sender and recipient on transfers
- UniversalReceiver function called with specific typeIds
- UniversalReceiverDelegate contracts for custom logic
- Enables auto-registration in LSP5 ReceivedAssets

### Force Parameter
- `force=false`: Transfer only succeeds if recipient implements LSP1 (safer)
- `force=true`: Transfer always succeeds (allows EOAs)
- Best practice: use `force=false` by default to prevent accidental token loss

### Gas-less Transactions
- LSP25 ExecuteRelayCall
- Users sign, relayers execute and pay gas
- Enabled via EXECUTE_RELAY_CALL permission
- Relayer API provides free monthly gas quota
