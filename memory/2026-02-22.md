### Token Claimer — Secret Drop Feature (commit `b763abe` + `a4558ff`)

**New 3rd drop type:** Secret Drop (`🔐` tab in create flow)
- Codes/links stored **off-chain in Vercel KV** (server-side Redis) — never on-chain
- Claimer proves UP ownership via **wallet signature** (sign-to-claim with 5-min expiry)
- Server verifies: signature valid, timestamp fresh, not already claimed, on-chain requirements met
- Then returns one code from the pool

**Architecture:**
- `frontend/app/lib/secret-drop.ts` — types: `SecretDropConfig`, `ClaimRecord`, `TokenReq`, `FollowerReq`
- `frontend/app/lib/server/verify-claim.ts` — server-side: `verifySig`, `parseClaimMessage`, `isFresh`, `checkOnChainRequirements`
- `POST /api/secret-drop/create` — creates drop (stores config + code pool in KV)
- `GET /api/secret-drop/[id]` — returns public drop info (no codes)
- `POST /api/secret-drop/[id]/claim` — verifies, atomically pops code via `LPOP`, returns code
- `frontend/app/secret-drop/[id]/page.tsx` — claim page with sign-to-claim UX

**Pool mode:** LPOP = atomic, each code given to exactly one person
**Shared mode:** One/few codes with configurable usage limit per code

**Access control per Secret Drop:**
- Token requirements: hold X of LSP7/LSP8 token (balance checked server-side via RPC)
- Min follower count via LSP26
- Must follow a specific UP address

**Anti-abuse:**
- One claim per address (stored in KV)
- Signature timestamp < 5 minutes old (replay prevention)
- LPOP atomic = no double-claiming under concurrency
